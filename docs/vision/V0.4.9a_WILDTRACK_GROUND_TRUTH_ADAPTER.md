# V0.4.9a — WILDTRACK Dataset + Ground-Truth Adapter

## Purpose

Atreides' venue-level output (camera-local tracks, cross-camera association,
venue-local temporary identity, occupancy) has, until this milestone, only
been checked against synthetic fixtures and closed-form maths. Real-world
validation needs a real, multi-camera, ground-truth-annotated dataset to read
against.

This milestone builds a **read-only adapter for the public WILDTRACK
pedestrian dataset**: it teaches Atreides' offline validation harness to
parse WILDTRACK's own images, per-frame JSON annotations and OpenCV camera
calibration, and to expose them as typed, WILDTRACK-scoped ground truth. It
adds no scoring, no benchmark numbers and no changes to any runtime signal or
identity path — those are separate, future milestones once this adapter
exists to feed them.

**WILDTRACK ground truth is offline validation truth only.** Its own person
identity (`personID`) is a different type in a different namespace from
anything Atreides' runtime treats as identity, and never reaches it.

## Architectural position

```text
services/vision/src/atreides_vision/venue_validation/datasets/wildtrack/
  __init__.py        re-exports the package's public surface
  cameras.py          fixed 7-camera naming, C<n> <-> calibration-file mapping
  time.py              WildtrackFrameId, frame-rate / annotation-cadence maths
  annotations.py       ground-truth domain models + per-frame JSON parsing
  layout.py            locating and validating one dataset root
  calibration.py       WILDTRACK OpenCV calibration -> Atreides CalibrationFit
  correspondence.py    ground-truth-only cross-camera correspondence/occupancy
  inspection.py        deterministic, non-identifying dataset summary
```

This is **validation infrastructure**, reachable only from
`atreides_vision.venue_validation` and its tests. Nothing under
`behavior/`, `interaction/`, `crowd/`, `zones/`, `association/`, `fusion/`,
`identity/` or `occupancy/` imports any module in this package, and this
package imports nothing from those signal layers either — it consumes only
Atreides' `calibration` and `models` primitives to build a `CalibrationFit`,
the same way any other calibration source would.

No dedicated `test_wildtrack_boundaries.py` was added. The existing
`test_venue_validation_boundaries.py` discovers every `.py` file under
`venue_validation` via `PACKAGE_ROOT.rglob("*.py")` and asserts, for each one,
allowed-import-prefix reach, absence of forbidden model libraries
(`rfdetr`, `trackers`, `supervision`, `cv2`) and forbidden names, and
non-inversion against every lower signal layer. That generic recursive scan
already fully covers `datasets/wildtrack/*.py` with no wildtrack-specific
exemption or special case, so a duplicate, dataset-specific boundary test
would only restate the same assertion under a new name.

## Public API

Re-exported from `atreides_vision.venue_validation.datasets.wildtrack`:

- **Cameras** — `CAMERA_IDS`, `calibration_name_for`, `camera_id_for_view_num`,
  `view_num_for_camera_id`.
- **Time** — `WildtrackFrameId`.
- **Annotations** — `WildtrackPersonId`, `WildtrackGroundPosition`,
  `WildtrackBoundingBox`, `WildtrackPersonAnnotation`,
  `WildtrackFrameAnnotations`, `load_frame_annotations`.
- **Layout** — `WildtrackDatasetLayout`.
- **Calibration** — `WildtrackIntrinsic`, `WildtrackExtrinsic`,
  `WildtrackCameraCalibration`, `load_camera_calibration`,
  `to_ground_plane_calibration`.
- **Correspondence** — `WildtrackCrossCameraCorrespondence`,
  `WildtrackGroundTruthOccupancy`, `cross_camera_correspondences`,
  `ground_truth_occupancy`.
- **Inspection** — `WildtrackDatasetInspection`, `inspect_dataset`.

Every entry point that touches the filesystem takes a `pathlib.Path` (a
dataset root, or a `WildtrackDatasetLayout` already built from one) supplied
by the caller. Nothing in this package hardcodes the real dataset's location;
the real, locally-extracted ~7.1 GB release lives outside the repository at a
path only the caller (a human, a diagnostic script, or a future validation
runner) knows, and is never committed to version control.

## Dataset structure, verified locally

Confirmed by reading the actual extracted release, not assumed from
documentation:

```text
<root>/
  Image_subsets/
    C1/00000000.png  C1/00000005.png  ...  (401 frames per camera, step 5)
    C2/...  ...  C7/...
  annotations_positions/
    00000000.json  00000005.json  ...      (400 frames, step 5)
  calibrations/
    intrinsic_zero/intr_CVLab1.xml  ...  intr_IDIAP3.xml
    extrinsic/extr_CVLab1.xml       ...  extr_IDIAP3.xml
```

`WildtrackDatasetLayout.load` validates this shape structurally rather than
by hardcoded counts: every camera directory must hold the same set of frame
ids as every other camera; every annotation frame id must be a subset of the
image frame ids (never the reverse); every one of the seven cameras must have
both an intrinsic and an extrinsic calibration file; and the first image's
PNG `IHDR` chunk (24 bytes, no full PNG decode) supplies `image_width` /
`image_height`. A differently-sized WILDTRACK-shaped release — more or fewer
frames, one camera missing an image — is a `WildtrackDatasetError`, not a
silently accepted smaller dataset.

### 401 image frames vs. 400 annotation frames

WILDTRACK extracts frames from its seven synchronized GoPro streams at 10 fps
(`FRAME_RATE_HZ = 10.0` in `time.py`) but only annotates every fifth extracted
frame (`FRAME_STEP = 5`), i.e. at `FRAME_RATE_HZ / FRAME_STEP == 2.0` Hz. Over
one recording that yields one more extracted frame than annotated frame — the
trailing extracted frame simply has no annotation file. This adapter encodes
the *relationship* (`annotation_frame_ids ⊆ image_frame_ids`,
`len(image) > len(annotation)`), not the literal numbers 401/400, so it keeps
working against any WILDTRACK-shaped release, not only the one currently on
disk.

## Frame and time semantics

`WildtrackFrameId(value)` is a frozen dataclass validating `value >= 0` and
`value % FRAME_STEP == 0`. `filename_stem` renders the canonical 8-digit
zero-padded WILDTRACK filename (`00000005`); `venue_seconds = value /
FRAME_RATE_HZ` gives the annotation's position in the recording, purely as
arithmetic on the frame value — never derived from wall-clock time.

## Camera mapping

`CAMERA_IDS = ("C1", ..., "C7")` is Atreides' own canonical ordering
(`viewNum`/`camIdx` 0–6), used everywhere in this package for deterministic
iteration. WILDTRACK's calibration files instead name cameras by rig:
`CVLab1..CVLab4` and `IDIAP1..IDIAP3`. `CALIBRATION_NAME_BY_CAMERA_ID` fixes
the mapping `C1..C4 -> CVLab1..CVLab4`, `C5..C7 -> IDIAP1..IDIAP3`, justified
by the calibration directory's own contents (exactly four `CVLab*` and three
`IDIAP*` files) corroborated by the WILDTRACK paper's own hardware listing
(GoPro Hero 3 for cameras 1–4, Hero 4 for cameras 5–7, matching the CVLab/
IDIAP split). `calibration_name_for`, `camera_id_for_view_num` and
`view_num_for_camera_id` all raise `WildtrackDatasetError` on an unknown id.

## Annotation / ground-truth schema

Each `annotations_positions/<frame>.json` file is a JSON array of person
records:

```json
[
  {
    "personID": 122,
    "positionID": 456826,
    "views": [
      {"viewNum": 0, "xmin": 1510, "ymin": 139, "xmax": 1561, "ymax": 299},
      {"viewNum": 1, "xmin": -1, "ymin": -1, "xmax": -1, "ymax": -1}
    ]
  }
]
```

`views` always has exactly seven entries, one per `viewNum` 0–6.
`WildtrackFrameAnnotations.from_json` rejects a non-array top level, a
missing required field, a wrong `views` length, and a repeated or
out-of-range `viewNum` or `personID`. All numeric fields must be JSON
integers (`bool` explicitly rejected, since Python's `bool` is an `int`
subtype). `WildtrackFrameAnnotations.persons` is always stored sorted by
`WildtrackPersonId`, independent of the source array's order, so two parses
of the same file content are byte-identical regardless of upstream ordering.

**Visibility sentinel semantics.** Following the official WILDTRACK
annotations viewer, a view is considered visible only when none of
`xmin`/`ymin`/`xmax`/`ymax` equals `-1`. Any occurrence of `-1` — on all four
fields or on just one — makes that view non-visible; no bbox is exposed for
it. This matches the official toolkit's own rule (`-1 not in
_box.values()`) and the WILDTRACK paper's description of the positions file
("positions which are not visible in a given view are assigned coordinates
of -1"), and is stricter than an earlier draft of this adapter that only
recognized the all-four-`-1` shape and raised an error on any other `-1`
occurrence. The real, locally-extracted corpus was found to contain views
with exactly one sentinel field and three real, positive pixel values in
roughly a quarter of its annotation files; these are accepted here as
ordinary non-visible views under the official rule. This adapter does
**not** interpret such records as an image-boundary-clipping convention —
no authoritative WILDTRACK source establishes that reading — so no
clipped/partially-visible bbox is exposed for them, only `NOT_VISIBLE`. A
"visible" record (no `-1` present) is still validated normally, e.g.
`xmax < xmin` is still rejected.

## Global ground-truth identity semantics

`WildtrackPersonId` is WILDTRACK's own stable identity for one annotated real
person across the whole recording — evaluation truth about the dataset, never
a runtime identity. It is a distinct, frozen, ordered dataclass, deliberately
not `VenueSubjectId` or a tracker integer, so nothing can pass one where the
other is expected. Only an offline evaluator comparing Atreides' own output
against this ground truth may ever hold both a `WildtrackPersonId` and a
`VenueSubjectId` at once; no module in this package, and nothing in
`association`, `fusion`, `identity` or `occupancy`, ever constructs or
receives one from the other.

## Visibility and cross-camera correspondence semantics

`WildtrackPersonAnnotation.visible_in(camera_id)` / `.visible_camera_ids`
report which cameras, per WILDTRACK's own annotation, saw a given person at
that instant, in canonical `CAMERA_IDS` order. `cross_camera_correspondences`
turns one frame's annotations into one
`WildtrackCrossCameraCorrespondence` per person — the camera set WILDTRACK
itself asserts belongs to the same real person — answering the same question
`atreides_vision.association` answers from Atreides' own tracks, but computed
here purely from `personID`, never from anything Atreides produced.
`is_single_camera` marks a person seen by exactly one camera as a normal,
expected outcome, not a degenerate one, consistent with single-camera being
a first-class case throughout the venue-validation path.

## Ground-truth occupancy definition

`ground_truth_occupancy` reports two deliberately distinct counts:
`full_scene_person_count` (every annotated person at the frame, regardless of
camera visibility) and `observed_person_count` (people visible in at least
one camera of an optionally restricted `considered_camera_ids` set; defaults
to all seven). The two coincide only when every camera is considered and
every annotated person is visible somewhere. Camera-set order never affects
the result — only membership does — and `considered_camera_ids` on the
returned record is always re-sorted into canonical `CAMERA_IDS` order. This
module contains no comparison logic against Atreides' own output; it is only
the truth side a separate evaluator would use.

## `positionID` / ground-plane semantics

WILDTRACK's own `README.txt` defines a fixed 480×1440 ground-plane grid, 2.5
cm cell spacing, origin at `(-3.0, -9.0)` metres:
`X = -3.0 + 0.025*(ID % 480)`, `Y = -9.0 + 0.025*(ID // 480)`. This is
reproduced verbatim (not re-derived) in
`ground_position_from_position_id`, with the grid constants
(`GRID_WIDTH`, `GRID_HEIGHT`, `GRID_SPACING_M`, `GRID_ORIGIN_X_M`,
`GRID_ORIGIN_Y_M`, `MAX_POSITION_ID`) exported so validation code never has
to re-hardcode them. `WildtrackGroundPosition` carries both the integer
`position_id` and the derived `(x_m, y_m)`.

## Calibration parsing

Each camera ships two small OpenCV `FileStorage`-format XML files:
`intr_<name>.xml` (a 3×3 `camera_matrix` plus 5 `distortion_coefficients`,
under the `intrinsic_zero` directory — deliberately chosen over
`intrinsic_original` because every one of its distortion coefficients is
exactly `0`, confirmed by reading all seven shipped files directly, so no
distortion model is needed to project through it) and `extr_<name>.xml` (a
Rodrigues rotation vector `rvec` and translation `tvec`, OpenCV convention
`X_cam = R(rvec) @ X_world + tvec`).

`_read_matrix` (for `camera_matrix` / `distortion_coefficients`) requires a
`<data>` child element; `_read_vector` (for `rvec` / `tvec`) reads text
directly on the tag with no `<data>` child — an asymmetry present in the
shipped files themselves and enforced, not smoothed over, by using two
separate parse helpers.

`rotation_matrix_from_rvec` implements Rodrigues' formula in plain NumPy (no
`cv2` dependency — this adapter never imports `cv2`, keeping model-library
confinement intact even though the format's *name* is OpenCV's).
`project_world_point` applies the pinhole model and returns `None` when a
point is behind the camera (`camera_point[2] <= 1e-6`), modelling "no finite
image position" explicitly rather than returning a physically meaningless
pixel.

**`tvec` units.** WILDTRACK's `positionID` formula and Atreides' own venue
points are both in metres. Projecting a `positionID`-derived ground point
through the raw, as-printed `tvec` does not land near the matching bounding
box in the dataset's own `rectangles.pom`; dividing `tvec` by 100 does,
closely and consistently, checked directly on two independently-oriented
cameras (`CVLab1` and `IDIAP1`). `tvec` is therefore centimetres and is
scaled by `TVEC_CM_TO_M = 0.01` before any downstream use — an empirical
finding from this dataset's own files, not assumed from external
documentation, and recorded as such in the module docstring.

## Atreides calibration compatibility / conversion

`to_ground_plane_calibration` converts one WILDTRACK camera's raw calibration
into an Atreides `CalibrationFit` — the same type every other calibration
source in the codebase produces. It samples a deterministic grid of
`positionID`-derived ground points (every `_SAMPLE_STRIDE`-th cell along each
grid axis, `_SAMPLE_STRIDE = 24`, always in the same personID-independent
order), projects each through the pinhole model, keeps only points that land
in front of the camera and inside the released image bounds, and builds
`PointCorrespondence` pairs from the survivors. It raises
`WildtrackDatasetError` if fewer than 4 correspondences survive (too few to
fit a homography) and otherwise hands the correspondences to Atreides' own
`atreides_vision.calibration.fitting.fit_calibration` — the same homography
solver every other calibration path in the codebase uses; this module never
re-implements calibration fitting, and any `CalibrationError` that solver
raises (e.g. too-collinear points) propagates unchanged. The resulting
`GroundPlaneCalibration.venue_id` is fixed to `VENUE_ID = "wildtrack"`,
naming this one specific published dataset's own coordinate frame rather than
inventing a general-purpose default.

## Runtime-vs-ground-truth isolation

- No module in this package imports `atreides_vision.association`,
  `atreides_vision.fusion`, `atreides_vision.identity` or
  `atreides_vision.occupancy`, and none of those layers imports anything from
  `venue_validation.datasets.wildtrack`.
- No module in this package imports `rfdetr`, `trackers`, `supervision` or
  `cv2` — this package parses WILDTRACK's own file formats directly (JSON,
  OpenCV `FileStorage` XML text, raw PNG header bytes), with no model-library
  dependency of its own.
- `WildtrackPersonId` never flows into `TrackObservation`, `AssociationEngine`,
  fusion or `VenueSubjectRegistry` — enforced by type distinctness (there is
  no conversion function from one to the other anywhere in the codebase) and
  by the layer-boundary rule above.
- Boundary coverage is generic (`test_venue_validation_boundaries.py`'s
  recursive `.py` scan), not wildtrack-specific — see "Architectural
  position" above for why no dedicated boundary test file was needed.

## Determinism

- `WildtrackFrameAnnotations.persons` is always canonically sorted by
  `WildtrackPersonId`; parsing the same JSON content twice, or with the
  source array's people listed in a different order, produces byte-identical
  output.
- `cross_camera_correspondences` iterates `frame.persons` in that same
  canonical order.
- `ground_truth_occupancy`'s `considered_camera_ids` is always re-sorted into
  canonical `CAMERA_IDS` order regardless of the order the caller passed.
- `inspect_dataset` iterates `layout.annotation_frame_ids` (already sorted at
  layout-validation time) and, within each frame, the already
  personID-sorted `persons` — never a filesystem or dict iteration order.
  Two calls against the same layout produce `==` results and identical
  `to_record()` output (covered by
  `TestInspectDataset.test_determinism_across_repeated_calls`).
- `to_ground_plane_calibration`'s ground-point sampling order is fixed by the
  `_SAMPLE_STRIDE` grid walk, independent of any `personID` or filesystem
  order; two calls against the same calibration and layout produce an
  identical `CalibrationFit.as_flat_tuple()` (covered by
  `TestToGroundPlaneCalibration.test_determinism_of_sampled_correspondences`).
- Nothing in this package reads the wall clock or uses unseeded randomness.

## Failure semantics

Every failure mode in this package raises `atreides_vision.errors.
WildtrackDatasetError` — a missing dataset root, camera directory, annotation
file or calibration file; an empty camera or annotation directory; frame ids
that disagree across cameras; an annotation frame with no corresponding image
frame; a malformed or wrong-shaped annotation record or calibration XML; a
`positionID` or `personID` outside its valid range; a non-finite calibration
value; a non-positive focal length; or too few in-bounds ground samples to
fit a calibration. `CalibrationFit`-fitting failures inside
`fit_calibration` itself (e.g. too-collinear correspondences) propagate as
Atreides' own `CalibrationError`, unchanged, rather than being caught and
re-wrapped — this package does not mask that solver's own diagnostics.

## Tests added

Seven new test files under `services/vision/tests/`, all against tiny
synthetic WILDTRACK-shaped fixtures built by the shared
`wildtrack_fixtures.py` helper module (never the real dataset):

- `test_wildtrack_cameras.py` — camera id / view-num / calibration-name
  mapping, including invalid-input rejection.
- `test_wildtrack_time.py` — `WildtrackFrameId` validation, `filename_stem`,
  `venue_seconds`, and the `FRAME_STEP` / `FRAME_RATE_HZ` cadence identity.
- `test_wildtrack_annotations.py` — JSON parsing happy path and every
  malformed-input rejection (bad top level, missing field, wrong `views`
  length, out-of-range/duplicate `viewNum`, mixed non-visible marker,
  duplicate `personID`), canonical-ordering behaviour, and
  `ground_position_from_position_id` boundary checks.
- `test_wildtrack_layout.py` — dataset-root validation happy path, the
  401-vs-400-shaped structural relationship (without hardcoding either
  count), path-building, and every missing/mismatched/malformed-structure
  rejection (including PNG header validation).
- `test_wildtrack_calibration.py` — intrinsic/extrinsic parsing (happy path
  and the `<data>`-child asymmetry between matrix and vector tags),
  `tvec_m` centimetre-to-metre scaling, Rodrigues rotation correctness,
  point-behind-camera projection, and `to_ground_plane_calibration`'s
  too-few-points failure, successful fit, and determinism.
- `test_wildtrack_correspondence.py` — cross-camera correspondence
  construction and ordering (including independence from input camera-set
  order), single-camera-visibility as a normal case, and ground-truth
  occupancy's full-scene vs. observed distinction under a restricted camera
  set.
- `test_wildtrack_inspection.py` — count/bound correctness, the 2 Hz
  annotation-cadence figure, empty-annotated-frame handling, determinism
  across repeated calls, and the absence of any filesystem path, timestamp
  or accuracy figure in `to_record()`.

`wildtrack_fixtures.py` builds a complete, valid, tiny (2×2-scale) synthetic
dataset root — a handful of frames, a 24-byte PNG header, minimal
`FileStorage` XML — reproducing the real layout, filename convention,
annotation schema and calibration XML shape without referencing the real
dataset's location or content anywhere.

## Explicitly out of scope

- Any benchmark scoring: no precision/recall, no ID-switch count, no
  association false-merge/missed-association rate, no occupancy MAE. This
  adapter produces ground truth and Atreides' runtime produces its own
  output separately; comparing the two is a distinct, future milestone.
- No threshold tuning of any runtime signal, association or fusion logic.
- No new association/confidence logic — `WildtrackCrossCameraCorrespondence`
  answers the *ground-truth* version of the same question `association`
  answers from real tracks; it is not wired into `association` itself.
- No use of `WildtrackPersonId` as runtime evidence anywhere.
- No ReID, embeddings or persistent identity of any kind.
- No entry/exit or cumulative counting logic.
- No Risk/Decision Engine, dashboard or API work.
- No CLI subcommand was added. The adapter is programmatic-only for this
  milestone (imported directly by tests and any future validation-runner
  code); a CLI surface, if wanted, is a small, separable addition once a
  concrete validation-runner consumer exists to justify its shape.
- No optional local/diagnostic script against the real dataset was added.
  `inspect_dataset` plus `WildtrackDatasetLayout.load` already give a
  five-line, non-hardcoded way to point at the real local dataset root ad
  hoc from a Python REPL or a throwaway script; a dedicated script did not
  seem to earn its keep as permanent repository content for something this
  small, but is easy to add on request.
- No V2/V3 sophistication (extreme-vision robustness, stronger ReID,
  long-gap association) — this remains a V1-scoped, offline validation
  adapter only.

## Known limitations

- The camera-name mapping (`C<n>` ↔ `CVLab*`/`IDIAP*`) is fixed to the one
  release currently on disk; a differently-arranged WILDTRACK-family release
  with a different rig-name split would need its own mapping table, not a
  code change to the parsing logic itself.
- `to_ground_plane_calibration`'s ground-point sampling stride
  (`_SAMPLE_STRIDE = 24`) is a fixed adapter constant tuned for the real
  dataset's known grid and camera geometry; it is not exposed as a tunable,
  consistent with this being validation infrastructure rather than a
  general-purpose calibration tool.
- This adapter has not yet been run end-to-end against the real 7.1 GB
  dataset in this session (only against synthetic fixtures, per the
  milestone's own scope); the `tvec`-centimetre finding and the
  `intrinsic_zero`-is-distortion-free finding were both established and
  recorded from the real files in a prior session, and are documented above,
  but a fresh full run of `inspect_dataset` / `to_ground_plane_calibration`
  against the live dataset root has not been repeated in this documentation
  pass.

## Next seam

A future milestone can build an offline evaluator that takes both Atreides'
own venue-level output (tracks, associations, venue-local identities,
occupancy) and this adapter's ground truth (`cross_camera_correspondences`,
`ground_truth_occupancy`) for the same WILDTRACK frames, and computes the
actual precision/recall/false-merge/occupancy-MAE figures explicitly left
out of this milestone's scope — using proxy vs. ground-truth figures kept
strictly separate, per the project's validation philosophy.
