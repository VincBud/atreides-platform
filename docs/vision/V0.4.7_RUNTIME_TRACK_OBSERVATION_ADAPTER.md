# V0.4.7 — Runtime TrackObservation Adapter

**Status:** implemented · **Engineering milestone:** V0.4.7 ·
**Product generation:** V1 · **Not production ready**

## Purpose

Every one of V0.4.0 through V0.4.6 documented the same acknowledged gap.
`venue_pipeline.py`'s own module docstring names it outright:

> "This milestone wires already-built `TrackObservation` values into association and
> fusion, it does not derive them from raw frames, pixels or camera-local tracks. That
> adapter — projecting a camera-local track into a venue-time-aligned,
> spatially-contextualised observation — needs calibration and projector access this
> milestone does not own... Building an observation is the caller's responsibility; this
> pipeline's contract begins at the observation."

Nothing before this milestone converts an already-running camera-local pipeline's own
state — a decoded `StreamFrame`, a projected `BehaviorSubjectSnapshot`, a camera's
`GroundPlaneProjector`, a camera's `CalibrationIntegrityGuard` — into the exact
`TrackObservation` the V0.4.x association/fusion/identity stack consumes.

V0.4.7 is that adapter, and nothing more. It adds no new perception, association or
identity intelligence. It establishes one explicit, truthful, deterministic conversion from
runtime state that already exists to the contract type that already exists, and it stops at
the edge of that conversion.

## Architectural position

```text
detection → camera-local tracking → calibration / spatial context
  → BehaviorAnalyzer.update()          (V0.3, unchanged)  -> BehaviorSubjectSnapshot
  → StreamFrame                        (V0.4.0, unchanged) -> venue time, stream identity
  → build_track_observation()          ← V0.4.7 builds this
  → TrackObservation                   (V0.4.1 contract, unchanged)
  → VenuePipeline.process_instant()    (V0.4.4, unchanged)
```

```text
services/vision/src/atreides_vision/
└── track_observation_adapter.py     # V0.4.7 — build_track_observation
```

`track_observation_adapter.py` is a single top-level module, placed alongside
`venue_pipeline.py` for the same reason that module gave for its own placement: each
existing package's boundary guard already forbids the cross-cutting reach this adapter
needs (`behavior` cannot see `association`; `association` cannot see `behavior` or
`calibration`), so the conversion lives at the top level, free to depend on the layers named
below, and on nothing else.

It performs **no association, no fusion, no venue-local identity, no ReID or appearance
matching, no trajectory smoothing or filtering, no topology or epoch inference, no new
calibration algorithm**, and it repairs no calibration or integrity finding a lower layer
already reported. Every field this module writes already exists somewhere in the runtime
named above.

## Public API

```python
def build_track_observation(
    snapshot: BehaviorSubjectSnapshot,
    frame: StreamFrame,
    *,
    calibration: GroundPlaneProjector | None = None,
    integrity_guard: CalibrationIntegrityGuard | None = None,
) -> TrackObservation: ...
```

No new type is introduced. `snapshot`, `frame`, `calibration` and `integrity_guard` are all
already-existing domain objects; a caller that has produced a `BehaviorSubjectSnapshot` for
this frame already has every argument this function needs in scope, because
`VideoProcessor.process(frame, sink)` already holds all four at the exact call site that
produces the snapshot.

## Field → source of truth

| `TrackObservation` field | Source | Unit / coordinate frame | Trust / uncertainty | Lossless? |
| --- | --- | --- | --- | --- |
| `subject` | `snapshot.subject`, unchanged | `(camera_id, track_id)`, camera-scoped | n/a — never a person, never mutated | yes, verbatim |
| `stream` | `frame.stream`, unchanged | `(camera_id, stream_epoch)` | `stream_epoch` is authoritative venue/session lifecycle state; never derived from frame index, track id, timestamp, filename or retry count | yes, verbatim |
| `frame_index` | `frame.frame_index`, unchanged | 1-based pipeline frame count, matching `TrackObservation.frame_index`'s own documented convention | n/a | yes, verbatim; cross-checked against `snapshot.frame_index` |
| `venue_seconds` | `frame.venue_seconds`, unchanged | session-relative venue seconds | n/a | yes, verbatim; cross-checked against `snapshot.timestamp_seconds` |
| `timing` | `frame.timing`, unchanged | `TimeUncertainty` | preserved exactly, including `TimeUncertainty.unknown()` when the stream's alignment basis was never established — never upgraded, never guessed | yes, verbatim |
| `position` | `snapshot.position`, unchanged | `MotionPoint` in whatever `MotionSpace` the camera's own projector already produced (normalized image fractions or ground-plane metres) | n/a — this is already the V0.3 calibrated projector's output | yes, verbatim, never re-projected |
| `spatial.camera_id` | `frame.stream.camera_id` | — | cross-checked against `snapshot.subject.camera_id` and, if supplied, `calibration.camera_id` | derived, not fabricated |
| `spatial.space` | `snapshot.position.space` | — | — | derived, not fabricated |
| `spatial.venue_id` / `spatial.surface_id` | `calibration.venue_id` / `calibration.calibration.surface_id`, when `space.is_physical` | — | `None` for the non-physical (uncalibrated) case, matching `CameraSpatialContext`'s own invariant | derived, not fabricated |
| `spatial.calibrated_region` | `VenueRegion.covering(calibration.calibration.venue_points())`, when metric | metres | — | derived from the calibration's own correspondence points; `None` when uncalibrated |
| `spatial.trust` | `GeometryTrust` narrowing of `integrity_guard.state` / `.metric_output_allowed` (see below) | — | see below | derived, not fabricated |

## `stream_epoch` and provenance

`stream_epoch` is read only from `frame.stream.stream_epoch` — the same `StreamRef` that
`VideoProcessor.process(frame: StreamFrame, sink)` already receives from the venue/session
runtime that decoded `frame`. This adapter never increments, resets or infers an epoch: it
is authoritative V0.4.0 session state, passed through unchanged. A regression test proves
`(cam_a, epoch_0, track_7)` and `(cam_a, epoch_1, track_7)` remain distinct
(`TestStreamEpochProvenance`), so a stream restart on the same camera can never be silently
folded into the previous session's tracklet.

`subject` is likewise passed through unchanged from `snapshot.subject` — the exact
`(camera_id, track_id)` the camera-local tracker and `BehaviorAnalyzer` already produced.
No remapping, no global ID, no "lowest ID wins."

## Venue time and timing uncertainty

`venue_seconds` and `timing` come only from `frame: StreamFrame` — never wall-clock, never
raw FPS-derived time, never frame index used as a multi-camera clock. `snapshot.timestamp_seconds`
is not treated as a second source of truth: it is cross-checked against `frame.venue_seconds`
and a mismatch raises, because a snapshot and a frame that disagree about venue time were
never produced by the same pipeline pass together, and building an observation from them
anyway would let one frame's calibration or integrity state attach to a different frame's
position. When a stream's alignment basis was never established, `frame.timing` is already
`TimeUncertainty.unknown()`, and this adapter passes that through unchanged — it never
upgrades an unknown to a declared value.

## Spatial position and calibration trust

`position` is reused verbatim from `snapshot.position` — the same `MotionPoint` the V0.3
calibrated projector (or the uncalibrated `NormalizedFrameProjector`) already produced. No
new homography, no raw pixel fallback, no guessed pixel→metre scale, no appearance feature
of any kind enters this module.

`GeometryTrust` is derived from `CalibrationIntegrityGuard`, honouring both pieces of state
the guard already exposes rather than only its most recent individual check:

```python
if integrity_guard is None:
    trust = GeometryTrust.UNVERIFIED
elif integrity_guard.state is IntegrityState.DRIFT_DETECTED:
    trust = GeometryTrust.UNTRUSTED
elif not integrity_guard.metric_output_allowed:
    trust = GeometryTrust.UNTRUSTED
elif integrity_guard.state is IntegrityState.CONSISTENT:
    trust = GeometryTrust.VERIFIED
else:
    trust = GeometryTrust.UNVERIFIED  # UNCHECKED or INSUFFICIENT_EVIDENCE
```

This matches `GeometryTrust`'s own documented mapping table for every `IntegrityState`
value, and additionally honours the guard's sticky suppression: once a guarded-mode run has
permanently withheld metric output for detected drift, `metric_output_allowed` never
re-extends on its own, and neither does the `GeometryTrust` this adapter reports — even if a
later individual check happens to read `CONSISTENT` again. A test
(`test_guarded_suppression_stays_untrusted_even_after_a_later_consistent_read`) proves this
directly. No integrity guard deployed at all produces `UNVERIFIED`, the same honest default
`CameraSpatialContext` already uses — absence of monitoring is not evidence of either
consistency or drift.

## Failure semantics

`build_track_observation` raises `AssociationError` — the shared error hierarchy's own type
for "association is asked for the impossible" — for every structurally impossible input:

- `snapshot.subject.camera_id` disagrees with `frame.stream.camera_id`.
- `snapshot.frame_index` disagrees with `frame.frame_index`.
- `snapshot.timestamp_seconds` disagrees with `frame.venue_seconds`.
- `calibration` is supplied and names a different camera than `frame`.
- `snapshot.position.space` is physical but no `calibration` was supplied (fabricating a
  scale would invent a metre value nobody measured).
- `snapshot.position.space` is physical but `calibration.space` disagrees with it.
- `snapshot.position.space` is not physical but a `calibration` was supplied anyway.

No case is silently coerced into a valid-looking `TrackObservation`. No new exception type
was introduced; `AssociationError` already covers exactly this class of problem, including
`TrackObservation`'s own `__post_init__` checks for the same kind of contradiction.

## Determinism

The adapter is a pure function of its four arguments: no wall-clock, no randomness, no
iteration over an unordered collection. Calling it twice with the same inputs produces an
identical `TrackObservation` (proved by `test_determinism_same_inputs_same_output_twice`),
and it mutates none of `snapshot`, `frame`, `calibration` or `integrity_guard`
(`test_inputs_are_not_mutated`).

## Single-camera behaviour

There is no special-cased path for one camera. A single-camera caller supplies
`calibration=None` and `integrity_guard=None` and receives a `TrackObservation` with
`GeometryTrust.UNVERIFIED` and a normalized-image `MotionSpace` — the same function, same
validation, same result shape a multi-camera caller uses.

## Downstream compatibility

`TestDownstreamCompatibility` in `test_track_observation_adapter.py` feeds
adapter-built observations directly into a real `AssociationEngine`:

- Two calibrated, verified, close observations from different cameras are found
  comparable (not rejected as `not_comparable`).
- Two observations built with a guard that has permanently suppressed metric output
  (`GeometryTrust.UNTRUSTED`) are gated to `not_comparable` — untrusted geometry never
  reaches a positive association.
- Two observations from the *same* camera are `not_comparable` regardless of position,
  matching association's existing same-camera exclusion — proving the single-camera path
  degrades exactly the way the existing engine already requires, with no adapter-side
  special case.

## Deliberate omissions (out of scope for this milestone)

- No CLI or validation runner wiring this adapter into `VideoProcessor` end to end.
- No multi-source/multi-camera orchestration loop.
- No occupancy product output wiring.
- No JSONL orchestration across streams.
- No new calibration algorithm or auto-repair of a calibration/integrity finding.
- No new behaviour signal, association rule, or confidence algorithm.
- No identity merge/split, ReID, embeddings, biometrics or persistent identity.
- No long-gap or non-overlap camera handoff logic.
- No occupancy smoothing or entry/exit accounting.
- No Risk/Decision Engine, no dashboard.

## Validation status

Synthetic/unit only, matching this repository's validation-philosophy discipline: this
milestone proves the conversion is a correct, truthful, deterministic mechanical mapping
against known runtime inputs. It says nothing about real-world camera integrity detection
accuracy, real calibration quality, or real multi-camera timing drift — those are each
already validated on their own terms by their own milestones (V0.3.3, V0.3.6, V0.4.0).

## Known limitations

- `build_track_observation` takes one snapshot and one frame at a time. A caller processing
  a full `BehaviorFrame` with multiple subjects calls it once per `BehaviorSubjectSnapshot`;
  this milestone does not add a batch/frame-level convenience wrapper, since one is not
  needed to satisfy the `TrackObservation` contract and would be speculative surface area.
- The adapter accepts a `GroundPlaneProjector` and a `CalibrationIntegrityGuard` as
  arguments rather than retrieving them from `BehaviorAnalyzer`, because
  `BehaviorAnalyzer` does not expose its internal projector publicly (by design — see
  V0.3's own module docstring). The composition root that already owns these objects
  (the same one that constructed the `BehaviorAnalyzer`) is expected to pass them through.
- No end-to-end wiring exists yet connecting `VideoProcessor`'s own per-frame loop to this
  adapter and onward to `VenuePipeline`. That orchestration — reading multiple streams,
  calling this adapter once per subject per frame, and driving `VenuePipeline.process_instant`
  — is the next seam.
