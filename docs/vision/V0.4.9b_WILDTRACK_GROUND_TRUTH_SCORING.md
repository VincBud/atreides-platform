# V0.4.9b — WILDTRACK Ground-Truth Scoring

## Purpose

V0.4.9a taught Atreides' offline validation harness to *read* the public
WILDTRACK seven-camera pedestrian dataset — images, per-frame JSON annotations,
OpenCV calibration — as typed, dataset-scoped ground truth. It added no scoring.

V0.4.9b adds the scoring: a **frozen offline evaluator** that compares Atreides'
own venue-level output (camera-local detection and tracking → calibration →
multi-camera association → fusion → venue-local temporary identity → occupancy)
against WILDTRACK ground truth, and a **single programmatic entry point** that
runs one real WILDTRACK session end to end through the production
`run_venue_validation` runtime and scores it.

This milestone establishes a **first real-CCTV-like baseline** for the
association and fusion stack. It is a measurement, not a tuning exercise: the
evaluator, its distance gate, the runtime configuration, the detector, the
tracker and the timing model were all committed *before* any real WILDTRACK
score was inspected, and none of them were changed in response to a number.

## What V0.4.9b does **not** establish

- **Not production readiness.** One public daytime campus dataset is not a pilot.
- **Not nightclub / target-venue accuracy.** WILDTRACK is outdoor daylight, ~2 Hz,
  fixed campus geometry. It says nothing about crowded indoor low light.
- **Not low-light, strobe, glare or motion-blur performance.** None are present.
- **Not arbitrary-venue accuracy.** One camera topology, one ground plane, one
  calibration quality.
- **Not persistent identity.** Venue-local identity here is session-scoped and
  discarded, exactly as everywhere else.
- **Not biometric recognition.** No face, gait, appearance template or
  re-identification network is used; WILDTRACK `personID` never enters the
  runtime and is used only for offline matching.
- **Not unique-visitor counting.** Occupancy here is instantaneous observable
  count per instant, not distinct people over time.
- **Not entry/exit or dwell accuracy.** Not measured.
- **No verdict.** The numbers below are ratios and distances, not a grade.

## Architectural position

```text
services/vision/src/atreides_vision/venue_validation/
  runner.py                         generic, dataset-agnostic venue-validation loop
  observer.py                       VenueValidationObserver protocol (read-only seam)
  datasets/wildtrack/
    runtime.py                      WildtrackStreamSpec: images + frame ids + timing
    session.py                      build_wildtrack_runtime_session -> real runtime config
    evaluation/
      config.py                     EvaluationConfig, frozen MAX_GROUND_PLANE_DISTANCE_M
      ground_truth.py               WildtrackGroundTruth (evaluator-only)
      matching.py                   deterministic local ground-plane matcher
      association.py / fusion.py / occupancy.py   per-instant scorers
      evaluator.py                  WildtrackEvaluator: streaming VenueValidationObserver
      models.py                     evaluation domain types + aggregation
      reporting.py                  deterministic JSONL / JSON artifacts
      scoring_run.py     (NEW)      run_wildtrack_scoring: the one entry point
```

`evaluation/` is loaded strictly *after* a venue instant has been produced. It
imports only `atreides_vision.association.models` /
`atreides_vision.fusion` domain types plus the WILDTRACK adapter — never the
association engine, gates, matcher, a tracker, a model library or a sibling
signal layer. The generic `venue_validation` recursive boundary test covers
every new file with no wildtrack-specific exemption.

### Runtime / ground-truth boundary

`run_venue_validation` is and stays **WILDTRACK-agnostic**. It walks a
`VenueValidationConfig`, and after association, fusion and occupancy have run for
each venue instant it calls an optional `VenueValidationObserver` once, in
order, with a read-only snapshot. It never calls `observer.finalize()`.

`WildtrackEvaluator` *is* that observer. WILDTRACK `personID` and all ground
truth live inside it, downstream of the observer boundary. Nothing flows back
into the runtime. `run_wildtrack_scoring` composes the two: build the session,
attach the evaluator as the observer, run, then call `finalize()` and write the
artifacts.

### The one entry point — `run_wildtrack_scoring`

```python
run_wildtrack_scoring(
    layout,
    *,
    output_dir,
    detector,                 # injected, already loaded — no model lib imported here
    tracker_factory,          # (TrackerConfig) -> MultiObjectTracker
    detector_config,          # stamped onto the run config to match the detector
    selected_camera_ids=None, # any order; run uses canonical C1..C7
    start_instant_index=0,
    instant_limit=None,
    calibrated=True,
) -> WildtrackScoringArtifacts
```

It builds no second runtime loop. There is **no** `max_ground_plane_distance_m`
parameter and no association/threshold parameter: retuning from the harness is
the frozen-scope violation the project forbids.

## Dataset and corpus semantics

- **7 cameras** `C1..C7`, 1920×1080, one shared outdoor ground plane.
- **400 GT-backed synchronized instants**, dataset frame ids `0, 5, …, 1995`
  (step 5). The trailing image frame `2000` has no annotation and is excluded
  structurally, not by a filter.
- **Declared cadence** `WILDTRACK_DECLARED_FPS = FRAME_RATE_HZ / FRAME_STEP =
  2.0` → venue seconds `0.0 … 199.5`.
- **Visibility rule.** A ground-truth person counts as *observable on a camera*
  only when that camera's WILDTRACK view marks the person visible with a
  bounding box; a person visible on no selected camera is not in that instant's
  observable ground truth.
- **Image-sequence source.** Each camera is an `ImageSequenceVideoSource` over
  its selected PNGs, reporting `fps_source = DECLARED`. No video decode, no
  resampling.
- **Calibration path.** Each camera's WILDTRACK OpenCV intrinsics + extrinsics
  are converted (V0.4.9a) to an Atreides `CalibrationFit` and injected via
  `VenueValidationCameraConfig.calibration_fit`. One homography, one plane.
  Integrity monitoring is not enabled (no reference frame is supplied).
- **Timing model.** `offset_seconds = 0.0`; `offset_accuracy_seconds = 0.05`
  (the 50 ms synchronization accuracy stated in the WILDTRACK publication). The
  session alignment resolves to an established half-width of 0.05 s; the
  ±0.10 s envelope is `offset ± 2·accuracy`.

## Frame alignment — ordinal, checked

The `k`-th snapshot the evaluator receives is scored against
`ground_truth.frame(k)` — the same ordinal as
`WildtrackRuntimeSession.scored_frame_ids[k]`. The evaluator additionally
requires `snapshot.venue_seconds == k / WILDTRACK_DECLARED_FPS` within
`venue_seconds_tolerance = 1e-6`. Too many instants, too few instants, or any
drift raises `ValidationError`. A stage subset may restart venue seconds at 0.0;
the 0.5 s cadence check continues to hold within the subset.

## Local ground-plane matcher

Per camera, per instant: runtime observations in
`MotionSpace.GROUND_PLANE_METRES` are matched to that camera's observable
ground-truth persons by Euclidean distance on the ground plane. The assignment
is **maximum cardinality first, then minimum total distance** among the
maximum-cardinality assignments. Ties are broken deterministically by
(ground-truth person id order, runtime observation order) so two equivalent runs
and two camera orderings produce identical matches. Only pairs within the frozen
gate are eligible.

### Frozen gate

`MAX_GROUND_PLANE_DISTANCE_M = 0.75`, inclusive (`distance <= 0.75`). Chosen
before any real score, as roughly one adult stride / half a body-width of
ground-plane slack for CCTV-grade calibration. Not tuned. Bumping it needs a new
milestone.

## Metric definitions

All ratios are reported as `{numerator, denominator, value}` with
`value = null` when the denominator is 0 (never a zero standing in for "no
measurement").

### Local perception / alignment

| Metric | Definition |
| --- | --- |
| `gt_visible_observations` | Σ over instants of (person, camera) pairs where GT marks the person visible on a selected camera |
| `runtime_observations` | Σ ground-plane runtime observations on selected cameras |
| `matched_observations` | Σ local matches within the 0.75 m gate |
| `local_observation_coverage` | `matched_observations / gt_visible_observations` |
| `unmatched_runtime_observations` | runtime observations with no GT match (localisation error, false positive, or GT-invisible detection) |
| `match_distance_stats` | mean / median / p95 / max of matched-pair ground-plane distance (p95 by nearest-rank) |
| per-camera `runtime_coverage` | `matched_count / metric_observation_count` |
| per-camera `ground_truth_coverage` | `matched_count / gt_person_count` |

### Association

Evaluated only on GT-resolvable cross-camera pairs — pairs of camera-local
tracklets that the local matcher tied to a GT person in the same instant.

| Metric | Definition |
| --- | --- |
| `true_positive_merges` | associated pairs whose two tracklets resolve to the **same** GT person |
| `false_merges` | associated pairs whose two tracklets resolve to **different** GT persons — the most serious class |
| `association_precision` | `true_positive_merges / (true_positive_merges + false_merges)` |
| `evaluable_pair_count` | GT-resolvable same-person pairs that *could* have been associated |
| `evaluable_associated_count` | of those, the ones the engine did associate |
| `association_recall_evaluable` | `evaluable_associated_count / evaluable_pair_count` — pairwise association, evaluable denominator |
| `missed_association_count` / `missed_association_rate` | GT-resolvable same-person pairs left not-associated |
| `ambiguous_pair_count` / `ambiguity_rate` | GT-resolvable same-person pairs whose outcome was *ambiguous* (first-class, not a merge) |
| `support_not_sustained_count` | pairs refused because temporal support did not persist |
| `not_evaluable_pair_count` | cross-camera pairs that could not be GT-resolved (one/both tracklets unmatched locally) |
| `end_to_end_pair_count` | *all* GT same-person cross-camera pairs, whether or not the runtime had a local tracklet for both endpoints |
| `association_recall_end_to_end` | `evaluable_associated_count / end_to_end_pair_count` — **the same successful `PairDecision == ASSOCIATED` opportunities as `association_recall_evaluable`**, over every GT-positive pair. Pairwise-association layer only; independent of fusion/identity state. |
| `end_to_end_satisfied_count` / `fused_identity_recall_end_to_end` | `end_to_end_satisfied_count / end_to_end_pair_count`, where `end_to_end_satisfied_count` counts GT-positive pairs whose two locally matched runtime tracklets are members of the **same `VenueSubjectId` after runtime association / fusion / identity integration** (`owner_a == owner_b`). A **later-stage pipeline metric** — distinct from association recall and never a substitute for it. |
| `decision_reason_counts` / `gate_reason_counts` | histogram of engine reasons |

### Fusion

| Metric | Definition |
| --- | --- |
| `evaluable_subject_count` | venue subjects with ≥1 GT-resolved contributing tracklet |
| `impure_subject_count` / `fusion_impurity` | venue subjects mixing ≥2 distinct GT persons |
| `persons_with_owned_match` | GT persons a venue subject "owns" (plurality of its resolved tracklets) |
| `fragmented_person_count` / `fragmentation_rate` | GT persons split across ≥2 venue subjects |
| `matched_tracklet_count` / `matched_unowned_count` / `matched_unowned_rate` | GT-resolved tracklets not attached to the subject that owns their person |
| `integration_outcome_counts` | histogram: applied / ignored / no_op / refused |
| `total_suppressed_duplicates` | Σ (raw active tracks − fused subjects) attributable to association |

### Occupancy

Per instant: `raw = active track count across selected cameras` (no
cross-camera dedup); `fused = venue subject count`; `gt = observable person
count`. Reported: `raw_mae`, `fused_mae`, `raw_bias`, `fused_bias`, `raw_rmse`,
`fused_rmse`, `improved / unchanged / worsened` instant counts,
`fused_minus_raw_mae`, `exact_fused_fraction`, `max_abs_*_error`.

## Deterministic artifacts

Written into `output_dir` (name only, never a path, inside either file):

| File | Contents |
| --- | --- |
| `wildtrack_evaluation.jsonl` | one `header` record (schema version, selected cameras, 0.75 m gate, instant count) then one `instant` record per scored instant, in order |
| `wildtrack_validation_summary.json` | the whole-run `WildtrackEvaluationSummary` (`schema_version = "0.4.9b"`), pretty-printed, key order stable |
| `false_merge_diagnostics.jsonl` | **only when ≥1 GT-resolved false merge**; `header` + one `false_merge` record per pair, ordered by `(dataset_frame_id, first_tracklet, second_tracklet)`. Absence of the file means "no GT-resolved false merge", not "not checked". |

No wall clock, PID, hostname, username, UUID, absolute path or run duration
enters any artifact. Two equivalent runs, and two camera orderings, produce
byte-identical files (regression-tested). Schema is additive-only under
`schema_version`.

## NO TUNING

After Stage A began, the following were frozen and **none was changed in
response to any Stage A/B/C figure**: detector model, detection confidence,
tracker and its config, `AssociationConfig`, fusion semantics, identity
semantics, calibration path, the 0.05 s timing uncertainty, the 0.75 m
evaluator gate, input resolution, and the Stage C camera set. The only code
changes in this milestone are the new `scoring_run.py` entry point, its export,
and its composition regression test. No correctness bug was found during
Stage A/B/C, so no runtime or evaluator code was modified.

`fused_identity_recall_end_to_end` is a **later-stage pipeline metric, not

over a wrong merge" posture holds. Recall is low and dominated by
`rival_not_separated` — the engine declining to merge when multiple candidates
are not geometrically separable in dense crowds at ~2 Hz — and by
`support_not_sustained`, i.e. tracklets too short at 2 Hz to accrue temporal
support.

## Measured failure decomposition (Stage C only)

Ordered by contribution to the end-to-end occupancy error.

**A — local perception / alignment (largest).** `local_observation_coverage`
0.415: 24932 of 42607 GT-visible person-camera observations are never recovered
within the gate. Matched-pair distances are *not* gate-saturated (p95 0.565 m,
max 0.749 m), and instant 0 has zero runtime observations on all seven cameras
(OC-SORT confirmation warm-up). So this is a detection-recall and
track-confirmation loss at ~2 Hz, **not** a calibration or projection error.
11292 runtime observations are unmatched (a mix of false positives, correct
detections of GT-invisible people, and localisation outliers beyond 0.75 m).

**B — association.** `association_recall_evaluable` 0.275
(`association_recall_end_to_end` 0.061 over all 83490 GT-positive pairs); 72.5 % of GT-resolvable
same-person pairs left ambiguous, dominated by `rival_not_separated` (9190) and
`support_not_sustained` (3292). Precision is 0.969 (160 false merges of 5240
merges) — the conservative posture holds; missed associations, not wrong ones,
are the cost. Note the `evaluable_pair_count` (18477) is itself suppressed by
A: pairs where either tracklet is unmatched locally fall into
`not_evaluable_pair_count` (65013).

**C — fusion.** `fusion_impurity` 0.170, `fragmentation_rate` 0.335. Fusion
impurity is materially non-zero at 17.0 %, despite high pairwise association
precision (0.969), indicating that erroneous associations can propagate into the
current venue-subject composition — Atreides treats false merges as costly, so
this is a substantial measured weakness, not a rounding detail. Fragmentation
(0.335) is the larger fusion-level effect and is downstream of B: tracklets
association did not link become separate venue subjects. 3547 integration
refusals show fusion declining unjustified merges.

**D — occupancy consequence.** Raw bias +48.6 (7 overlapping cameras, no
dedup); fused bias +38.8. Fusion improves 397/400 instants, worsens none,
suppresses 3939 duplicates — but ~15000 duplicate observations remain because
association recall is 0.275. The residual over-count is inherited from A+B, not
an occupancy-logic fault.

**E — multiple layers.** The dominant chain is **A → B → D**: unrecovered local
observations shrink the evaluable-pair set, low association recall leaves
cross-camera duplicates, occupancy inherits them. Fusion (C) behaves
conservatively and correctly throughout but cannot repair upstream misses.

## Representative failures (Stage C)

1. **False merge, frame 15 / 1.5 s** — `(C1, track 5)` person 18 merged with
   `(C7, track 6)` person 10 via `sustained_mutual_agreement`. Runtime
   ground-plane positions `[1.48, 14.73]` and `[1.88, 14.53]` are 0.45 m apart;
   both tracklets matched their (different) GT persons within the gate (0.29 m,
   0.31 m). Two genuinely distinct people standing close, merged. Class B false
   merge with a Class D consequence (two people counted as one).
2. **Label swap, frame 65 / 6.5 s** — a three-way tangle among persons 0 and 1
   across C1/C2/C6 whose GT positions are 0.78 m apart; the runtime associated
   across the wrong pairing in both directions. Geometry-only association is
   defeated by close proximity.
3. **Cold start, instant 0** — 0 runtime observations on all 7 cameras against
   155 GT-visible; OC-SORT hit/confirmation warm-up at stream start. Pure
   Class A, propagates to Class D (`raw_error` −38).
4. **Steady state, instant 399 / 199.5 s** — local coverage 0.46, association
   recall 0.21, 43 `rival_not_separated`, occupancy still +38 over GT. The
   aggregate behaviour is not a transient.

## Limitations

- One public dataset; outdoor daylight; fixed 7-camera campus geometry with
  designed overlap and good calibration — the opposite of the unconstrained
  CCTV V1 targets.
- ~2 Hz cadence: OC-SORT runs far below its usual frame rate, so track
  continuity here is not representative.
- The local matcher is a proxy: an unmatched runtime observation may be a
  localisation error, a false positive, or a correct detection of a
  GT-invisible person, and the evaluator cannot always tell which.
- Occupancy ground truth is instantaneous observable count, not unique
  visitors.
- `not_evaluable_pair_count` dominates the cross-camera pair space; association
  precision/recall are conditional on GT-resolvability and must be read with the
  local coverage figure.
- No integrity / calibration-loss condition is exercised.

## Recommended next milestone

Driven only by the Stage C decomposition above:

**Target local observation recall and the evaluable-pair denominator first — not
the association algorithm, not a distance threshold, not ReID.**

Evidence hierarchy (measured, Stage C):

- `local_observation_coverage` 0.415
- `association_recall_evaluable` (pairwise association) 0.275; `association_recall_end_to_end` 0.061
- `association_precision` 0.969
- `fusion_impurity` 0.170
- occupancy `fused_mae` 38.97

Rationale from the measurements:

- The single largest loss is Class A (`local_observation_coverage` 0.415), and
  it is a *recall* loss, not an alignment loss — the bulk of matched distances
  sit below the gate (p95 0.565 m) even though the tail reaches it (max
  0.749 m), so widening the gate would mostly admit worse matches rather than
  recover the missing 58.5 %.
- Association recall (0.275) and fusion impurity (0.170) are **also substantial
  measured weaknesses** — fusion is not "essentially solved". They are placed
  after A only because A shrinks the denominator both of them are measured
  against (65013 pairs are `not_evaluable` because a tracklet is unmatched
  locally), so their numbers cannot be trusted as representative until local
  recall improves. Association precision is already 0.969; the engine is
  correctly refusing merges it cannot separate.
- Nothing in the data indicates embeddings, a re-identification network, a
  larger detector or new hardware is *necessary* — those are V2 concerns and
  were not shown to be the bottleneck.

Concretely, the next milestone should study detection recall and tracker
confirmation behaviour at low frame rate (the ~2 Hz WILDTRACK cadence, the
cold-start instant-0 gap, per-camera coverage spread from 0.27 to 0.83), and
should keep this frozen evaluator as the unchanged yardstick so the effect is
measurable. Association-algorithm work follows once the evaluable-pair
population is representative. This document does not implement any of it.
